# 香港分红保单实现率数据库

> 纯本地静态数据库 + 网站：把香港主流保险公司按 GL16 强制披露的分红实现率（FR）
> 与总现金价值比率（TCVR）逐产品抓取、归一化，并做有意义的统计。
> 2026-09-05 由 Derek 与 WorkBuddy 共建。
> **当前状态：12 家全部接入（P0–P3 完成），17,789 数据点 / 4,265 有效值（2025 报告年度）。**

## 快速使用

```bash
PY=/Users/derek/.workbuddy/binaries/python/envs/default/bin/python

$PY scripts/run.py all --reparse      # 复用快照重解析（不重新抓）
$PY scripts/run.py all                # 重新抓取（保诚走 Playwright）
$PY scripts/build_dataset.py          # 合并 + 统计
$PY scripts/build_site.py             # 出网站（两套皮肤）
$PY scripts/qc.py PRU                 # 单公司体检
```

新增一家公司：在 `scripts/adapters/` 写一个适配器（参考 `sunlife.py`），
在 `config/insurers.json` 确认 `channel_hint`，在 `scripts/run.py` 的
`MODULES` 与 `scripts/qc.py` 的 `MODULES` 登记代码 → 模块映射。

## 统计口径（刻意避开简单平均）

1. **无数据 ≠ 0**。「已停售」「尚未推出」「不适用」是三种不同状态，一律不参与统计。
2. **保单年度 = 报告年度 − 生效年份**（永明 2025、友邦 2024 双源验证，不加 1）。
   「第 10 个保单年度+（2015 之前）」这类混合桶，保单年度以官网表头为准。
3. **产品类型必须分层**（储蓄 / 终身 / 年金 / 危疾 / 医疗）。
   永明官方只分「分红终身人寿 / 分红储蓄」两类，前者混装危疾与年金——
   因此分类以**产品名**为主判据、官方栏只作兜底。
4. **中位数优先**。港险实现率有极端值（早期保单演示基数低会算出上千百分比），
   均值会被拉走。主用中位数、P25/P75、达标率（≥100% / ≥90%）、离差中位数。
5. **个案演示不入库**。官网「个案一/二」是单个示例保单的营销追踪，
   不是 GL16 的产品级聚合口径。
6. **报告年度只用最新**，跨年度数据保留在 facts 供趋势分析但不混算。

## 已知坑（新增公司前必读）

- **保监局索引 URL 不可盲信**。索引给永明的 `savings-and-life` 路径只有「个案」表，
  真正的产品级数据在另一个路径。抓取前务必确认页面含产品级表格。
- **保诚把 FR 和 TCVR 拆成两个页面**，FR 页只放一句「按此查閱總現金價值比率」的链接。
  适配器需声明 `SOURCES = [(slug, url), ...]`。
- **保诚静态请求返回 481 字节空壳、宏利 403**，这类站点必须 Playwright。
- **表头可能跨多行**（保诚首行是跨列说明、次行才是年份），需扫描所有行取匹配最多的一行。
- **表头行与数据行列数可能不等**（数据行左侧多一个「貨幣」标签列），需按
  `len(数据行) - len(表头行)` 做偏移对齐。
- **繁简混杂**：永明简体、保诚繁体、友邦 PDF 繁体，词典需同时收录。
- **脚注标记**：保诚 `N/A(1)`、友邦 `已停售¹`、万通 API `N/A3(a)`，解析前需剥离。
- **requests 编码坑**（P1 新增）：中银/国寿页面响应头无 charset，requests 默认
  ISO-8859-1 会把中文毁成乱码再存档。fetch_base 已改为嗅探编码（apparent_encoding）。
- **响应式重复表**（P1 新增）：中银/汇丰同一表格有「桌面宽表 + 移动长表」两个 DOM，
  只解析一种（中银按 `--desktop` class 过滤，汇丰按表头特征过滤），再靠 fact_id 去重兜底。
- **产品名不一定在表格里**（P1 新增）：中银在折叠面板头部、恒生在 `data-key` 属性、
  周大福在容器内 `p.fzBold`——每家公司都要先定位产品名挂载点。
- **万通是 JSON API 站**（P1 新增）：页面壳由 `/aisite-applyapi/.../getDividend`
  与 `getTotalCash` 两个 POST 接口喂数据，产品清单在静态页 `.pro_select_list li`。
  API 响应同样归档 `data/raw/YF/{date}/api/`。万用寿险类产品（APEX 等 5 个）接口返回
  data:null——它们没有分红实现率，只有派息率，属正常无覆盖，不是抓取失败。
- **国寿海外只有扫描版 PDF**（P1 新增）：披露页正文是派息率表，FR 数据在一个
  无文本层的 PDF（11 页全图像），需要 OCR，暂挂起（见路线图 P1.5）。
- **国寿海外 FR 其实在内联 JS 数组里**（P1.5 实证，推翻上一条）：红利理念页的
  `<script>` 内嵌 `policyYears` + `dataSets1/2/3` 三个数组（週年/終期/累積利息），
  提取需 bracket-matching + 去尾逗号后 `json.loads`——**千万别用嵌套量词正则
  `re.findall(r"\[((?:...)+)\]")`，26KB 数组会灾难性回溯卡死**。
- **友邦数据在 XHR 拦截出的全量 JSON**（P2）：页面 `<select>` 是 `display:none`
  的自定义下拉，自动化点选会超时；Playwright 监听网络请求发现
  `content/dam/hk-wise/json/further-product-information/2026/fulfillment-ratio.json`
  一次给全 81 个产品（AD/TD/RB/TB 四个系列）。先抓 JSON 归档再解析。
- **hub → 产品页两级模式**（P2，安盛/富卫同款）：hub 页内嵌产品清单 JSON
  （安盛在 Playwright 渲染后的 DOM 里、富卫在 Next.js `<script application/json>`
  的 `pageProps` 里），逐产品页才是数据表。保监局索引给的 URL 可能是营销壳
  （安盛 `/zh/article/...`），真实 hub 路径需另行确认。
- **Akamai 级反爬要用真 Chrome**（P2，宏利）：curl / requests / 默认 Playwright
  Chromium 全部 403；`pw.chromium.launch(channel="chrome")`（本机真 Chrome 二进制）
  拿 200，且同会话 `ctx.request.post` 可继承信任调 tools 子域的 `ss1.php` API。
  宏利 FR 与 TCV 是两个独立工具目录（fulfillment-ratio-2024 / fulfillment-tcv-2024）。
- **requests 编码坑会「存档干净、解析为空」**（P2，富卫实测）：live 抓取时
  `r.text` 因无 charset 头按 ISO-8859-1 解码毁中文，正则全失配（69 页 0 行）；
  但归档的 `r.content` 字节是干净的，`--reparse` 一切正常。修复统一为：
  响应无 charset 时强制 `r.encoding = r.apparent_encoding or "utf-8"`。
- **宏利「不適用」脚注分四种原因**（P2）：1=无生效保单（每年红利）/无已终止保单
  （终期/TCVR）、2=演示金额为零、3=尚未推出、4=已停售——解析时按上标数字映射到
  不同 no_data_reason，且同产品不同「生效時期」分页目前只归档了默认期。

| 通道 | 静态直取 | Playwright × 2 页 |
