# 2026-09-05 开发与运维日志

## 故障排查与修复：Company Admin 发票图片 AI 识别失败

### [Status] 已完成

### [Bug 现象]
- 用户在 Company Admin 上传发票（如 `IMG_6514.jpeg`、`IMG_6515.png`）时，系统挂起数分钟后报错 500：`RuntimeError: 文件 [xxx] 所有页面识别均失败`。
- `backend_err.log` 显示 `openai._base_client` 在调用 OpenRouter `/chat/completions` 时出现 `Connection error.` 并连续超时重试。

### [根因分析]
1. 服务器于 2026-09-05 06:09 启动了 Tailscale，启用了 MagicDNS（将 `/etc/resolv.conf` 覆盖为 `100.100.100.100`）。
2. Tailscale 将外部域名查询转发给本机的 `systemd-resolved`（`127.0.0.53`）。
3. `systemd-resolved` 的默认上游为阿里云 DHCP 下发的内部 DNS：`100.100.2.136` / `100.100.2.138`。
4. Tailscale 防火墙存在规则：`-A ts-input -s 100.64.0.0/10 ! -i tailscale0 -j DROP`。由于阿里云内部 DNS 位于 `100.64.0.0/10` 网段，且通过物理网卡 `eth0` 响应，其 DNS 回包被 Tailscale 防火墙拦截丢弃。
5. 结果导致服务器全局无法解析外网域名（`openrouter.ai`、`api.deepseek.com` 等），发票识别 Vision API 请求无法发出并超时。

### [Change Log]
- 在阿里云轻量服务器 `/etc/systemd/resolved.conf.d/dns.conf` 中显式指定公网 DNS：
  ```ini
  [Resolve]
  DNS=223.5.5.5 223.6.6.6 8.8.8.8 1.1.1.1
  FallbackDNS=8.8.4.4
  ```
- 重启 `systemd-resolved` 使配置持久生效。
- 执行 `pm2 reload wonder-backend` 重载后端服务。

### [验证结果]
1. `dig openrouter.ai +short` 立即返回 IP（解析延迟 < 5ms）。
2. `curl -I https://openrouter.ai/api/v1/models` 返回 HTTP 200。
3. Python 真实调用 `scan_receipt` 识别发票图片样本，成功识别商户、日期、金额并完成实时汇率换算：
   - 凭证号：`EXP-202501-0005`
   - 商户：`满陇山房(深圳平安中心店)`
   - 金额：`1943.0 CNY` → 自动折算 `2098.44 HKD`
   - 置信度：`95`
